## Delivered behavior

The lobby leads with continuing stories and the player's identity. New stories
use three choices: my character, multiple AI characters, and a world/initial
scene. Persona and lore imports return to the same step as pending selections.
Character imports return selected native cards. Starting creates a native
WorldSession, independent player/character instances, scene cast and branch.
WorldBook selection is optional and scoped to the new session. Cast and player
feed entries use the player's name rather than a generic user label.

The importer supports V2/V3 JSON and PNG `chara`/`ccv3`, standalone lorebooks,
explicit Persona formats and single-persona ST backups, and prompt/preset
mapping. Preview precedes execution. Greetings, examples, CharacterBook,
prompts and unknown fields retain their semantic identity. Unknown/large
extensions live in an independently loaded compatibility payload, not the
frequently loaded CharacterCard summary. Source SHA supports duplicate checks;
copies require confirmation and same-name assets are never silently replaced.

Recognized lore rules become native Always/Keyword/Manual entries. Unsupported
rules are preserved with warnings. Character-specific prompt fields are consumed
only by character generation, below host rules. Preset prompt changes default
to preserve-only and require an explicit append/replace choice. They do not
silently overwrite World/Session prompts. Extractors and mutation validation
remain outside the character style layer.

## Database and cache

SQLite v11 adds `external_compatibility_payloads` and lightweight nullable
CharacterCard provenance/avatar references. Migration and incomplete-v11 repair
are additive. Tests cover old product rows, World Prompt metadata, reopen,
payload lazy reads, transaction rollback and optimistic preset conflicts.

Device smoke exposed a warm-cache issue: transactional imports bypassed the
read-through Character/Project repositories. A generic committed-entity cache
contract now publishes successfully committed entities without a second DB
write. A real SQLite regression warms both caches, imports two cards, validates
immediate reads and verifies failed transactions publish nothing.

The lobby also falls back to the scene name when its optional location is empty;
the existing onboarding widget regression checks this case.

## Security evidence and limitations

Imported scripts were not executed. Imported URLs were not opened. Import has
no HTTP/Provider client, SecureStorage writer, WebView or plugin registration
dependency. The later explicitly submitted player action is a separate ordinary
Core AI request, not execution of an imported extension. No claim is made of an
instrumented zero-network count for the entire running app.

Credential-shaped values are heuristically redacted from native and parsed JSON
fields and are never installed as provider configuration. Original PNG metadata
may remain in the private inert avatar file. The warning explicitly distinguishes
this from parsed-field redaction. This is not a universal secret detector.

The real local `a local test card` was statically parsed only: V3, two alternate greetings,
three lore entries, script-like extension values of 217233 and 18856 characters.
No original JavaScript/URL was executed. The source file is not included in the
repository or distributable fixtures.

## Known v1 limits

- No ZIP imports, full ST runtime, regex execution, Quick Replies or STscript.
- Multi-persona backup selection is deferred; ambiguous formats are rejected.
- Alternate greetings are preserved and viewable; greeting selection/insertion
  at new-session creation is deferred.
- Advanced lore recursion, sticky/cooldown, insertion/depth and probability
  execution are not emulated. Raw rules remain available for later remapping.
- Provider-specific samplers and preset prompt-order parity are preserved only.
- Persona avatar references are provenance, not remote downloads or arbitrary
  local-file reads.
- Character soft delete retains compatibility payload/avatar for restore.
