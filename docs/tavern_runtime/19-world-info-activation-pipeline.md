# Activation pipeline

1. Validate composite IDs, probabilities, timer values, insertion depth, settings and state scope. Sort entries by priority descending, order ascending, then book/entry ID. Prune deleted, disabled-book, disabled-entry, edited and expired timers from the proposed state.
2. For each pass, reject disabled/book-disabled, scope mismatch, generation mismatch, manual-only, recursion-only-at-pass-zero, recursion-excluded and delay-pending entries before keyword matching. Sticky candidates bypass keyword and probability checks; cooldown blocks a non-sticky reactivation.
3. Build each entry's scan text from the latest `scanDepth` projected messages, optionally overridden per entry, plus only its explicitly opted-in, supplied character/persona fields. Depth zero scans no chat text. Recursive passes additionally scan only the newly activated entries' content from the prior pass. Primary keys are OR; a non-constant entry needs at least one. Nonempty secondary keys use AND_ANY, AND_ALL, NOT_ANY or NOT_ALL. Constant ignores key matching but still passes all other gates.
4. Group competing candidates, with sticky candidates preferred. Optional score keeps the highest count of matched keys; prioritized groups choose highest entry order, then stable ID; otherwise a keyed weighted sample chooses the winner. Group losers are terminal for this activation cycle, even if recursion continues. Probability is sampled after group filtering, once per candidate per cycle. Sticky does not reroll. A probability failure is terminal for the cycle.
5. Activate winners once. Only activated content from entries that allow further recursion feeds the next pass. Stop on no newly activated text or `maxRecursionPasses`; an already active entry is never emitted again. The trace records recursion pass/source and guarded repeats.
6. Emit one optional World Info `PromptSource` per active composite ID. The compiler alone decides final token budget and insertion order. No separate World Info token cap is applied in v1.

Case folding and whitespace compaction are shared by primary and secondary matching. Plain single-word ASCII keys use Unicode letter/number boundaries when whole-word mode is on. CJK keys use substring matching so unspaced Chinese/Japanese text remains usable. Multiword keys use substring matching after whitespace normalization. Regex keys and macro expansion are deliberately not evaluated in v1.

Scan depth counts visible projected messages; insertion depth counts retained Prompt history units after compiler trimming. They are independent. A source's entry `priority` maps to `PromptSource.priority`; its `order` maps to `PromptSource.order`; placement and role are passed through. World Info does not re-sort the final compiled prompt.
