# Timed state and lifecycle

State is keyed by `(sessionId, storyLineId)` and composite `(bookId, entryId)`. Each timer stores the activation message count and an ephemeral definition signature. Delay requires at least N visible projected messages, including for constant entries. For activation at message M, sticky N covers M+1 through M+N; cooldown C then covers M+N+1 through M+N+C. Consequent matching does not refresh sticky. Sticky bypasses probability and wins its group. Cooldown also blocks recursive reactivation. An edit changes the definition signature and resets that entry's effect. Disabling/deleting an entry or book prunes its effect. A reduced/replaced transcript invalidates prior timers.

`evaluate` returns a proposed next state. `WorldInfoAttemptLedger` owns the transient committed state and adopts a plan only once for a completed Foundation Generation Attempt with matching Prompt Compiler outcomes. Preview, failure and cancellation discard it; a stale plan cannot replace newer state. An activated entry dropped by compiler budget does not start or retain a timer. This is an intentional World Next transaction boundary: a failed AI request cannot consume lore timers. State is transient in v1; restart resets timed effects. No persistent event log exists from which probabilistic/group activations can be reconstructed exactly, so v1 does **not** claim ST restart parity. The [v2 proposal](24-world-info-acceptance.md) covers migration, archive/restore and conflict merge before adding a table.

Branches have separate state. A new branch may use `forkAt(childStoryLineId, branchPointMessageCount, childHistoryMarker)` on a parent state snapshot at its origin; only effects activated at or before the branch point are copied. Later activity on either branch cannot mutate the other. A caller without a branch-point snapshot starts with empty child state. Passing a state with the wrong session/story-line identity is rejected.
