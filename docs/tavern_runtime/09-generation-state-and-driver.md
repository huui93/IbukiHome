# State machine and driver contract

The runtime handle starts `preparing`, emits `streaming` for visible/reasoning deltas, then exactly one of `completed`, `cancelled`, or `failed`. Persisted Attempts progress from queued to running and a terminal status. Transient animation, current token and pending delta text are not canonical database state. `handle.updates` is a broadcast stream; `handle.snapshot` supplies the latest state to late subscribers and `handle.done` resolves once terminal persistence settles.

The driver exposes a `Stream<TavernGenerationEvent>` for one immutable `TavernGenerationTarget`. v1 events are typed visible text delta, reasoning delta, completion, and classified failure. A future adapter can add typed usage or tool-call events without granting it repository access. Events with another Attempt ID are ignored. Driver stream termination without completion becomes an invalid-response failure. An optional inactivity timeout becomes a timeout failure; neither path stores raw exception text as a domain reason.

Stop is idempotent. It marks a cancellation token, cancels the stream iterator, and serializes terminal persistence with other events. The first terminal persistence outcome wins; late deltas, repeated completion and repeated Stop cannot reopen an Attempt. `dispose()` cancels and awaits active handles; it does not rely on garbage collection. The shared in-process scope registry accepts at most one active handle per Session even across Runtime instances; separate Sessions can progress independently. A command ID replay for the same target returns its handle while a collision with a different target is rejected.

Repository batch writes keep one transaction per bounded group of Parts rather than per token. The final batch, terminal status and conditional Alternative selection use one transaction. A failed write cannot expose a half-completed answer. Flush thresholds are a transport/UI responsiveness tradeoff, not a schema property. A Driver receives only stable target identity and a cancellation signal; it cannot create Turns, Alternatives, Attempts or Content Parts through the Driver interface. Runtime core imports no Flutter UI or prototype DTO.
