# World Info Runtime v1

`WorldInfoRuntime.evaluate` is the formal, synchronous, provider-independent activation entry point. It takes selected `WorldInfoEntry` projections from any number of books, a `WorldInfoActivationContext`, an immutable session/story-line state, settings, and an injectable keyed random source. It returns `WorldInfoActivationPlan`: activated composite IDs, one `PromptSource` per activated entry, an activation trace, and a proposed next state. Evaluation never mutates assets, Tavern Foundation, Generation Runtime, or the input state. The application-facing `WorldInfoAttemptLedger` binds a plan to one Foundation Generation Attempt, checks the terminal outcome and compiler trace, and settles it once. Failed/cancelled generations do not advance effects. See [acceptance policy](24-world-info-acceptance.md).

`WorldInfoScanContextBuilder.fromProjection` consumes the Foundation transcript projection through `PromptHistoryAssembler`, not raw rows. Normal includes the current player input; Regenerate excludes the old target and later turns; Continue includes the selected target answer. Only selected, completed, visible text is scanned by default. Reasoning, events, attachments, unselected alternatives, and failed/cancelled partials are excluded. An explicit option may scan the `text` field of a structured Tool Result. Per-entry opt-in may scan provided character/persona descriptions, personality, scenario or notes; the caller must supply only knowledge-safe text. No attachment parsing, regex, macro, vector search, network call, or Provider operation occurs.

The native adapter converts existing `LoreEntry` fields only after the caller resolves WorldBook references and session overrides. It never reads or executes ST compatibility payloads or script-like metadata. Advanced ST fields not represented in native data require an explicit, reviewed runtime projection before use. The Runtime itself does no SQLite query and creates no new schema. SQLite stays v13 and archive format is unchanged.

The activation result is eligibility, not final prompt inclusion. The Prompt Compiler may drop an active source by its own budget; its compile trace remains separate. `PromptOrigin` carries book ID, entry ID and label, allowing a future Inspector to join both traces without copying the lore body.
