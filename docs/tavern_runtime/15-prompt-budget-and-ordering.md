# Budget and ordering

The caller supplies maximum context, reserved output and reserved control tokens. Usable input is their difference; invalid negative budgets fail. A caller-supplied `PromptTokenCounter` estimates each candidate exactly once. The built-in estimator is approximate, not a model tokenizer. Required sources are reserved first and fail with `requiredOverflow` if they cannot fit; they are never silently truncated. Optional grounding sources are selected by descending priority, then ascending explicit order and ID. History is selected newest-first as a contiguous window of whole Turns. Supplemental sources fill remaining space by the same deterministic tie-break. Optional sources are included whole or dropped; v1 does not substring-trim character identity, World Info or RAG chunks.

The reservation is subtracted exactly once by `PromptCompileConstraints.usableInputTokens`; a future Provider adapter supplies the window and reservations, then verifies its actual wire payload without making a second compiler budget deduction. A counter exception or negative estimate is a typed `tokenCounterFailure`, never a partial success. Optional empty or whitespace-only text sources are dropped with `empty`; a required empty source fails. A nonempty source estimated at zero tokens remains included and visible in the trace. The counter contract can be replaced by a model-aware implementation without changing selection or ordering.

Final order is independent of selection order: before-character, after-character, before-history, retained history with depth insertions, after-history, tail. Depth zero is after the newest retained history Turn; depth N is N Turns before it and clamps to the oldest boundary. Sources sharing a slot sort by priority descending, explicit order ascending, then stable source ID. History sorts chronologically by explicit order and ID. Source providers must assign meaningful order; database natural order and timestamps are not consulted.

Depth is measured against retained history after budget selection, not original history length. Thus a depth beyond the retained window clamps before the oldest retained Turn, including when no history remains. One History source represents one complete projected Turn with all policy-eligible Content Parts; duplicate Turn origins and a History source assigned a non-History budget class are invalid compile inputs. This prevents accidental half-Turn trimming. A policy may exclude a typed Part (for example private reasoning), but budgeting never substrings a surviving Part.

An estimated total never exceeds usable input. Provider adaptation may add wire overhead or reject unsupported roles/media; it must validate against actual model capabilities and tokenization before sending. Such adaptation does not give the Provider permission to silently drop required content or reorder sources.
