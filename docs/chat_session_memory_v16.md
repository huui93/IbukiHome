# 本地会话记忆 v16

本轮按用户确认的边界实施：上下文、已保存记忆、摘要、历史检索和记忆控制均属于单个聊天会话。同一人格的其他会话不能读取这些内容。小说的业务数据与运行流程继续独立；模型/API 配置仍可共用。

## 参考范围

参考 OpenAI 公开的 [Memory in ChatGPT](https://help.openai.com/en/articles/8590148-memory-in-chatgpt) 和 [ChatGPT memory dreaming](https://openai.com/index/chatgpt-memory-dreaming/) 中的产品行为：已保存记忆与历史引用区分、可修订的概览、相关记忆检索、来源查看和遗忘控制。

这不是 ChatGPT 私有后端的复刻。检索采用本地词法排序，包含中文单字/双字词、英文词、少量查询扩展、固定记忆优先、去重、数量和字符预算。没有接入远端向量服务，也没有下载本地语义嵌入模型。同义表达或指代不明确时可能漏检，不能承诺 ChatGPT 的语义召回效果。现有应用也没有 ChatGPT 的连接应用、云端同步或独立临时聊天生命周期。

## 本地数据及调用

- `chat_memory_entries`：按 session_id 保存的事实条目，支持手动修改、固定、删除与恢复；v16 补充主题和来源指纹。
- `conversation_summaries`：会话片段摘要，保留来源范围和指纹。读取时重新校验，编辑或删除源消息后，过期摘要及对应自动事实不再注入。
- `chat_memory_states`：每个会话独立的引用开关、历史开关、自动保存、暂停、概览、处理游标和来源排除规则。
- `chat_memory_usage`：回答实际收到的参考来源 ID 和内容版本指纹。只记录提供给模型的参考，不能证明模型每个结论的内部成因。来源变更或遗忘后不展示其新内容为旧回答的来源。
- 检索文档从当前本地行构建；检索本身不调用模型。自动生成摘要和提取事实仍使用本会话选择的模型/API，并发送当前会话的相关资料。未配置模型时不伪报整理成功。

已有记忆与原始消息分开保存；关闭引用不删除原始消息。暂停记忆会同时停止引用与整理，最近会话上下文和聊天记录继续保留。“清空并关闭”把已保存记忆移入已删除、停止摘要和旧历史来源引用，并关闭开关，不删除聊天记录。不再引用是来源及明确内容范围内的控制，不等同于永久擦除所有原始聊天文本或所有可能的同义表达。

## 生成与整理

聊天提示词保留最近 30 条原始消息，额外检索较早消息、有效摘要及相关已保存记忆；固定记忆有优先权。额外来源最多 8 条、正文总计最多 6000 字符，单来源最多 1400 字符。历史引用关闭时只使用允许引用的已保存内容。手动修订优先于自动摘要，当前用户说明优先于旧事实。

后台同一会话仅运行一个整理任务。较早历史沿用 20 条批处理；新会话也可在累计 8 条消息时整理。显式提示和手动整理可提前触发。历史引用开启时生成片段摘要，自动保存开启时提取长期事实。失败不推进游标，以便重试；每个会话使用自身模型绑定。

自动提取要求只记录用户明确说出或确认的事实，不把 AI 建议当作用户经历；敏感信息要求明确记忆意图。主题一致的自动事实可更新，固定或手动修订条目受保护。模型提取仍可能出错，管理界面支持查看原始来源和修订。

明确的“记住：内容”可直接本地保存；明确指明内容的“忘记……”可停止引用对应已保存条目。模糊指代不自动删除。重新生成已回答的旧消息不重复执行记忆操作。自动摘要和遗忘排除不把已排除的原始批次重新发去整理。

模型请求之外读取状态版本，返回后再次校验来源前缀，最后以事务比较状态版本并原子提交事实、摘要和游标。设置、手动编辑及遗忘会推进版本，阻止旧任务覆盖用户操作。数据库不跨模型请求持有事务；条目更新另有递增版本及会话来源检查。

## 迁移与备份

SQLite 15 升级到 16；App 仍为 1.0.0+1，依赖未升级。旧人格级开关在会话首次初始化时复制为该会话的初值，此后互不联动。没有安全会话归属的旧记忆保留为只读数据，不自动分配或注入。

新表不依赖 SQLite JSON SQL 函数，JSON 由 Dart 校验。备份包含会话设置与回答来源。冲突合并会重写会话、消息、事实、摘要及 JSON 内部引用；仅对原本匹配来源的指纹重建新 ID 下的指纹。无效 JSON 或跨会话关联导致恢复事务回滚。
