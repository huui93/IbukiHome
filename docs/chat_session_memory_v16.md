# 本地会话记忆

**简体中文** · [English](chat_session_memory_v16.en.md)

本文适用于伊吹之家 Android v1.1.0、SQLite v22。文件名中的 v16 为最初引入会话独立记忆的数据库迁移版本。

本轮按用户确认的边界实施：上下文、已保存记忆、摘要、历史检索和记忆控制均属于单个聊天会话。同一人格的其他会话不能读取这些内容。小说的业务数据与运行流程继续独立；模型/API 配置仍可共用。

## 参考范围

参考 OpenAI 公开的 [Memory in ChatGPT](https://help.openai.com/en/articles/8590148-memory-in-chatgpt) 和 [ChatGPT memory dreaming](https://openai.com/index/chatgpt-memory-dreaming/) 中的产品行为：已保存记忆与历史引用区分、可修订的概览、相关记忆检索、来源查看和遗忘控制。

这不是 ChatGPT 私有后端的复刻。检索采用本地词法排序，包含中文单字/双字词、英文词、少量查询扩展、固定记忆优先、去重、数量和字符预算。没有接入远端向量服务，也没有下载本地语义嵌入模型。同义表达或指代不明确时可能漏检，不能承诺 ChatGPT 的语义召回效果。现有应用也没有 ChatGPT 的连接应用、云端同步或独立临时聊天生命周期。

## 本地数据及调用

- `chat_memory_entries`：按 session_id 保存的事实条目，支持手动修改、固定、删除与恢复；v16 补充主题和来源指纹。
- `conversation_summaries`：会话片段摘要，保留来源范围和指纹。读取时重新校验，编辑或删除源消息后，过期摘要及对应自动事实不再注入。
- `chat_memory_states`：每个会话独立的引用开关、历史开关、自动保存、暂停、概览、处理游标和来源排除规则。
- `chat_memory_usage`：回答实际收到的参考来源 ID 和内容版本指纹。只记录提供给模型的参考，不能证明模型每个结论的内部成因。来源变更或遗忘后不展示其新内容为旧回答的来源。
- 检索文档从当前本地行构建；检索本身不调用模型。自动生成摘要和提取事实仍使用本会话选择的模型/API，并发送当前会话的相关资料。未配置模型时不伪报整理成功。

已有记忆与原始消息分开保存；关闭引用不删除原始消息。暂停记忆会同时停止引用与整理，最近会话上下文和聊天记录继续保留。“清空并关闭”把已保存记忆移入已删除、停止摘要和旧历史来源引用，并关闭开关，不删除聊天记录。「停止引用」按消息来源 ID 和明确匹配的内容过滤，作用于记忆检索和下一次模型请求中的最近原文。主动发出的新消息按当前输入处理。原文仍可在聊天记录中查看。

## 生成与整理

聊天请求优先保留当前消息与最近 30 条原始消息。开启历史引用时，在预算内延续尚未纳入摘要的连续历史，并加入最新有效摘要、关键词匹配的旧消息和已保存记忆。额外来源最多 8 条，正文总计最多 6000 字符，单来源最多 1400 字符，实际注入额度随模型配置调整。固定记忆和手动修订优先。使用已保存的模型上下文和输出额度，模型未知时采用保守的文本估算预算。

后台同一会话仅运行一个整理任务。默认累计 50 个完整轮次后压缩，用户发言加正常完成的 AI 回复算一轮。可在「设置 → 聊天记忆 → 当前会话」修改轮数或立即压缩。压缩按消息数量和文本大小分批，历史引用开启时保存摘要，自动保存开启时提取长期事实。每个会话使用自身模型绑定。暂停或关闭整理时会取消当前任务，并阻止发起后续整理请求。

自动提取要求只记录用户明确说出或确认的事实，不把 AI 建议当作用户经历；敏感信息要求明确记忆意图。主题一致的自动事实可更新，固定或手动修订条目受保护。模型提取仍可能出错，管理界面支持查看原始来源和修订。

启用自动保存且记忆未暂停时，图片识别一成功就把模型观察保存为本会话的来源绑定记忆。该写入不额外调用模型、不等待压缩，也不把画面推测当作用户事实。关闭自动保存时，描述仍附在原图片记录里，可在本地历史检索。

明确的“记住：内容”可直接本地保存；明确指明内容的“忘记……”可停止引用对应已保存条目。模糊指代不自动删除。重新生成已回答的旧消息不重复执行记忆操作。自动摘要和遗忘排除不把已排除的原始批次重新发去整理。

模型请求之前读取状态版本，返回后再次校验来源前缀，最后以事务比较状态版本并提交结果。摘要成功而事实提取失败时保存有效摘要，保留待处理游标，重试优先复用这一摘要。设置、手动编辑及遗忘会推进版本，阻止旧任务覆盖用户操作。数据库不跨模型请求持有事务；条目更新另有递增版本及会话来源检查。

## 迁移与备份

SQLite 从 v15 升级到 v16 时引入会话独立记忆。旧人格级开关在会话首次初始化时复制为该会话的初值，此后互不联动。没有安全会话归属的旧记忆保留为只读数据，不自动分配或注入。

新表不依赖 SQLite JSON SQL 函数，JSON 由 Dart 校验。备份包含会话设置与回答来源。冲突合并会重写会话、消息、事实、摘要及 JSON 内部引用；仅对原本匹配来源的指纹重建新 ID 下的指纹。无效 JSON 或跨会话关联导致恢复事务回滚。

## 验证

引入会话独立记忆时新增 27 项自动化测试，包含同人格双会话隔离、独立开关、检索相关性和预算、停止引用、失效来源、模型失败重试、并发关闭/遗忘、主题更新、保护手动事实、来源版本、小屏幕与键盘、v15 升级、数据库重开、空库恢复与冲突合并。

原阶段全量 1746/1746 通过。v1.1.0 发布时静态分析通过，离线全量测试 1,893 项通过、19 项跳过。真实模型的摘要质量和召回效果取决于会话所用模型。[v1.1.0 验证记录](https://github.com/huui93/IbukiHome/releases/tag/v1.1.0)
